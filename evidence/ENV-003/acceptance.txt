Deviation from the planned step, and why
---------------------------------------
Planned: "forge install OpenZeppelin/openzeppelin-contracts@v5.7.0" as a git submodule.
What happened: forge registered the submodule in the ROOT .gitmodules with the path
"lib/openzeppelin-contracts" (relative to impl/contracts, not to the repo root), so git
created .git/modules/lib/... but never checked any files out. The install reported success
while the directory did not exist.
Resolution: dependencies are now vendored as plain files via `forge install --no-git`,
impl/contracts/lib/ is git-ignored, and impl/scripts/install-deps.sh re-creates them from
the pinned tags (verified by re-running it from an empty lib/). This also removes submodule
init as a step in the clean-clone check (DOC-006).
Cost of the alternative: committing the vendored tree would have added 15 MB / 1041 files.
